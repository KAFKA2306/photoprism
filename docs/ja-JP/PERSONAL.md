# 個人版の正準仕様

## 目的

写真を「ファイルの山」として保管するのではなく、旅行、場所、文章、月、人物、アルバムを介して後から思い出せる個人アーカイブにする。

優先順位は次の順です。

1. 自分の写真を安全に保持する
2. 旅行と時系列から探せる
3. 写真と文章を同じ記憶単位に結び付ける
4. 数枚の写真と短い文章で月を振り返れる
5. 必要なものだけ共有・公開できる
6. AIは補助に限定し、正準データを勝手に書き換えない

## UI の中心

一般的な管理画面ではなく、次の4入口を中心にする。

- **思い出**: Moments / 月次日記 / AI候補
- **旅行**: 場所、国、都市、日付、アルバム
- **日記**: 月次本文と写真
- **共有**: 自分が明示的に公開した写真・月だけ

既存の写真検索、アルバム、Calendar、Moments、Places はこの目的に使える限り再利用する。

## 日本語専用

- UI言語は `ja` を唯一の選択肢にする。
- 新規の利用者向け文書は `docs/ja-JP/` に置く。
- 上流の英語文書は移行中に残っていても「個人版の正準文書」とは扱わない。
- 最終ゲートでは、本forkで利用者が読む文書を日本語へ統一し、不要な上流文書を削除する。
- `LICENSE`、ソースヘッダ、第三者ライセンスなど法的原文は翻訳・削除しない。

## AI の境界

AIは次を提案できる。

- 写真説明
- 場所・旅行の候補
- 月次要約の下書き
- タグ候補
- 「この月の代表写真」候補

AI出力は観測データと分けて保存し、人間の確定操作なしに正準の日記本文や公開状態を変更しない。

## プライバシー

- 既定は非公開。
- 静的公開では `visibility: public` のデータだけを書き出す。
- APIキー、OAuthトークン、セッショントークンは写真メタデータや日記JSONへ保存しない。
- 外部AIへ送る写真はユーザーが明示的に選択したものに限定できる設計とする。
- 公開成果物からローカルパス、内部ID、秘密情報を除外する。

## 削除完了の定義

機能を削除するときは、以下すべてを満たして初めて完了とする。

- route がない
- component / backend handler がない
- config / feature flag がない
- 文書・翻訳・画像・テストが参照していない
- navigation / help / about から到達できない
- grep ベースの残骸監査が 0 件
- build / test が通る
